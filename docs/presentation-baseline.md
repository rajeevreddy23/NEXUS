## slide3.xml
Abstract Modern cloud-native applications consist of interconnected services, databases, APIs, containers, and infrastructure components. When failures occur, developers must manually analyze metrics, logs, and traces to identify the root cause and determine a recovery action. This process is time-consuming, particularly for small development teams without dedicated Site Reliability Engineering support. NEXUS is an autonomous agentic platform designed to detect failures, perform intelligent root-cause diagnosis, and coordinate safe recovery in cloud-native systems. It continuously monitors CPU usage, memory consumption, latency, error rates, database connections, logs, and distributed traces. When abnormal behavior is detected, specialized AI agents perform log analysis, dependency analysis, historical incident retrieval, root-cause identification, recovery planning, safety evaluation, and incident documentation. Its AI Incident Memory stores symptoms, root causes, attempted fixes, successful remediation steps, and preventive actions. Using Retrieval-Augmented Generation and vector similarity search, NEXUS retrieves similar incidents for future investigations. An interactive Failure Graph displays service dependencies and probable failure paths. Proposed recovery actions are safety-checked and tested in an isolated environment before developer approval. Overall, NEXUS aims to transform traditional reactive incident handling into an intelligent workflow of  Detect → Investigate → Remember → Diagnose → Recommend → Validate → Recover → Learn , enabling faster and more explainable software recovery while maintaining operational safety. 3

## slide4.xml
Introduction Cloud applications increasingly rely on microservices that communicate through APIs and shared infrastructure. Although this architecture supports independent development and deployment, failures can spread across dependencies and become difficult to diagnose. Engineers must interpret monitoring data and connect symptoms across services before selecting suitable recovery actions. Research on multimodal failure diagnosis and language-model-based incident recommendations provides a foundation for supporting this process. NEXUS proposes an autonomous agentic platform that combines application monitoring with specialized AI agents for investigation, historical incident retrieval and developer-approved recovery. It aims to help small development teams investigate incidents systematically and retain knowledge from resolved failures. 4

## slide5.xml
Problem Statement When an application fails, developers often need to examine logs, compare metrics and inspect service dependencies across separate tools. Historical incident knowledge may be scattered or incomplete, increasing the effort required to identify causes and choose recovery steps. AI-generated recommendations can also lack supporting evidence or suggest actions that do not suit the current environment. The proposed work addresses the need for a system that connects incident detection with evidence-based diagnosis and controlled recovery. NEXUS will investigate how monitoring data and retrieved incident knowledge can support useful remediation recommendations while preserving developer approval and verifying application health after execution. 5

Objectives of Proposed Work Monitor service health and detect failures using logs and metrics. Identify likely root causes using telemetry and service dependencies. Retrieve similar historical incidents to support diagnosis. Generate remediation plans with supporting evidence and rollback steps. Execute predefined recovery actions after developer approval. Verify recovery and store incident outcomes for future retrieval. Evaluate detection time, diagnosis accuracy and recovery success. 6

## slide7.xml
Proposed System: Monitoring NEXUS continuously monitors CPU usage, memory consumption, latency, error rates and database connections. Logs and distributed traces provide evidence for investigating abnormal behavior. When the platform detects a failure, specialized AI agents investigate the incident and support root-cause diagnosis. The proposed system connects monitoring with recovery planning and incident documentation. Telemetry helps relate resource pressure to changes in service performance. Continuous observation supports incident detection before diagnosis and recovery planning. 7

## slide8.xml
Specialized AI Agents Log analysis agents examine failure-related messages and runtime events. Dependency analysis agents investigate affected services and their relationships. Historical incident retrieval supports root-cause identification using similar past failures. Recovery planning and safety evaluation agents assess proposed remediation actions. Incident documentation agents retain the investigation and recovery details. Root-cause identification combines findings from logs, dependencies and incident history. Agent coordination connects investigation, diagnosis and recovery planning. 8

## slide9.xml
AI Incident Memory Incident Memory stores symptoms, root causes and attempted fixes. Successful remediation steps and preventive actions remain available for future investigations. Retrieval-Augmented Generation (RAG) uses stored incident knowledge to support diagnosis. Vector similarity search retrieves incidents with related symptoms or failure patterns. This memory allows NEXUS to reuse lessons from previously investigated failures. Attempted fixes provide context when comparing recovery options for a new incident. New incident records extend the knowledge available for later investigations. 9

## slide10.xml
Failure Analysis and Safe Recovery The proposed interactive Failure Graph displays service dependencies and probable failure paths. Agents use incident evidence to identify likely causes and recommend recovery actions. Proposed actions undergo safety evaluation and testing in an isolated environment. Developer approval controls whether recovery actions proceed. Incident records capture attempted fixes, successful remediation and preventive actions. Application health checks assess whether recovery restores expected service behavior. Remediation plans include rollback steps to support controlled execution. 10
